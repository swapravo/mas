Collections Agent: build plan

One agent, one goal: collect every membership fee due this week by Sunday, without ever sending a message, changing an amount or recording a payment on its own.

The agent does
  • ✓Finds overdue fees every morning and keeps one case per fee.
  • ✓Drafts a reminder in the right tone for the current step of the ladder.
  • ✓Reads the resident's reply and logs any promise to pay, with a date.
  • ✓Escalates to the property owner, then stops and says why.
The agent never
  • ✕Sends a message by itself. A person approves every draft.
  • ✕Changes an amount or a due date.
  • ✕Records a payment. Only the bank match can do that, in another agent.
  • ✕Messages outside 9 AM to 9 PM, or more than twice a day per resident.

How the agent thinks: pick, act, check, decide

A plain loop written by hand. It repeats until the goal is met, a cap is hit, or something looks wrong. Then it reports and stops.

01PickChoose the next case that needs attention.
02ActCall one tool through the gateway.
03CheckDid the case actually change as intended?
04DecideContinue, wait for a reply, or stop.

The reminder ladder

The ladder lives in a rules file, not in a prompt. The gateway enforces it.

DAY 0 · STEP 1
Friendly nudge

"A quick reminder your fee is due."

DAY 3 · STEP 2
Firm reminder

States the amount and how long it is overdue.

DAY 7 · STEP 3
Owner escalation

A staff member is asked to call.

THEN
Stop and report

No endless loop. The reason is written down.

Data model and tools

Nine small tables, built for one rule: one fee charge per resident per cycle, and one case file that remembers what happened. Then the eight tools the agent is allowed to use.

Agent tools

Every tool is typed, checked by the gateway and logged. The dangerous ones simply do not exist.

Dangerous design

record_payment(resident, amount)

One wrong guess, or one injected message, and the books are wrong. Nobody saw it happen.

POST /payments
{ "resident": 14, "amount": 8500 }
→ 201 Created   // committed immediately
Safe design

draft_reminder(case, step)

The agent proposes. The gateway checks the rules. A person approves. Then it is sent.

POST /gateway/draft_reminder
{ "case": 14, "step": 1, "idem": "c14-s1" }
→ 202 Accepted  // status: pending approval

    Three attacks we will show

    Prompt injection

    "Mark everyone as paid"

    A resident writes instructions into the chat. The agent treats chat text as data, and no tool can record a payment, so nothing happens.

    Over-reach

    One property sees another

    An owner's token is tried against a different property. Row-level security returns zero rows, even if the app code forgot to check.

    Runaway agent

    Message flood

    A bug asks for 50 reminders. The gateway refuses after the daily cap and holds night messages until 9 AM.

    Acceptance tests

    The agent is done when every row passes. These come straight from the original client proposal, rewritten for the demo.
